# Project Scope: Role-Based Product Management System (REST API)

## 1. Database Collections

Create a MongoDB database with the following collections:

1. **Users** – Store user details, hashed passwords, roles, account status, and timestamps.
2. **Roles** – Store roles: Super Admin, Admin, and User.
3. **Categories** – Store both categories and subcategories in a single collection, distinguished using a `type` field (`category` or `subcategory`) and a `parentCategory` reference.
4. **Products** – Store product details, price, category reference, subcategory reference, and timestamps.

## 2. Authentication and User Management

- Implement secure login and JWT-based authentication.
- The Super Admin can create Admin and User accounts by providing their details.
- Upon account creation, send a confirmation email containing a secure, autogenerated temporary password or password-setup link.
- Implement password hashing, password change, forgot password, and reset password functionality.
- Super Admin and Admin can view, add, edit, activate/deactivate, and delete User accounts according to their permissions.
- Only the Super Admin can create Admin accounts.
- Prevent unauthorized role changes and privilege escalation.

## 3. Dashboard

- Display total products, categories, subcategories, and users.
- Display category-wise product counts.
- Display subcategory-wise product counts.
- Use MongoDB aggregation pipelines for all required dashboard statistics.

## 4. Product Management

- Implement APIs to add, view, edit, and delete products.
- Allow product listing with pagination, search, filtering, and sorting.
- Each product must belong to a valid category and subcategory.
- Ensure the selected subcategory belongs to the selected category.
- The product listing must include product name, description, price, category name, and subcategory name.
- Use MongoDB aggregation pipelines with `$lookup` to retrieve related category and subcategory details.

## 5. Category Management

- Implement APIs to add, view, edit, and delete categories.
- Display category names along with their associated subcategories.
- Include product counts where required.
- Prevent deletion of categories that have dependent subcategories or products unless a defined reassignment or cascading deletion strategy is implemented.

## 6. Subcategory Management

- Implement APIs to add, view, edit, and delete subcategories.
- Each subcategory must belong to an existing category.
- Display subcategory names along with their associated category names.
- Include product counts where required.
- Prevent a subcategory from being assigned to another subcategory.

## 7. Role-Based Access Control

**Super Admin**

- Full access to user management, products, categories, subcategories, and dashboard statistics.

**Admin**

- Manage User accounts, products, categories, and subcategories according to assigned permissions.
- Cannot create Admin or Super Admin accounts or modify Super Admin privileges.

**User**

- Access product, category, and subcategory management operations according to the defined permission policy.
- Cannot access user administration or modify roles and permissions.

## 8. MongoDB Aggregation Requirements

- Do not use Mongoose `populate()`.
- Use MongoDB aggregation pipelines, including `$lookup`, `$match`, `$group`, `$unwind`, `$project`, `$sort`, and `$count` wherever appropriate.
- Use aggregation to retrieve related category and subcategory names, category-wise and subcategory-wise product counts, and dashboard statistics.
- Apply appropriate validation and indexes to maintain data consistency and query performance.
